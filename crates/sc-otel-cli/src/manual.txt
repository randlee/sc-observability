QUICK START
  sc-otel log --body 'job started'
  sc-otel span --name build --start-time-unix-nano 1700000000000000000
  sc-otel metric --name jobs.completed --kind counter --value 1

  Each command builds one native OpenTelemetry record and exports it with the
  official OTLP/HTTP protobuf exporter before the process exits. No Tokio
  runtime, local database or background worker is involved.

CONFIGURATION
  Endpoint: --endpoint, then OTEL_EXPORTER_OTLP_ENDPOINT, then
  http://localhost:4318. The signal path (/v1/logs, /v1/traces, /v1/metrics)
  is appended, so per-signal *_ENDPOINT variables are not consulted.

  Headers: OTEL_EXPORTER_OTLP_HEADERS and the per-signal *_HEADERS variables
  are sent with every request. --header NAME=VALUE replaces a header of the
  same name. Keep credentials in the environment rather than on the command
  line. Header values and endpoint user information never appear in errors.

  Resource: --service sets service.name; otherwise OTEL_SERVICE_NAME and
  OTEL_RESOURCE_ATTRIBUTES apply as in the OpenTelemetry SDK.

  TLS: https endpoints verify certificates against the system roots plus any
  --root-certificate PEM file. Verification cannot be disabled.

ATTRIBUTES
  --attributes takes one JSON object of string, boolean and number values,
  inline, as @FILE, or as - to read standard input:
    sc-otel log --body done --attributes '{"job":"build","attempt":2}'
  Input is limited to 1 MiB and 10,000 attributes. Null, array and object
  values are rejected.

EXIT CODES
  0  The exporter reported success.
  1  Unexpected internal failure.
  2  Command-line usage error; inspect stderr and --help.
  3  Input or configuration rejected; nothing was exported.
  7  The export failed: the collector was unreachable, timed out or rejected
     the request. Nothing is retried after the process exits.

  Success means the collector accepted the request. For metrics, the
  OpenTelemetry SDK 0.33.0 reports a failed export without the HTTP cause.

DOCUMENTATION
  Run sc-otel <command> --help for options and examples.
  The Markdown manual and website reference are generated from this same Clap
  help at every release; their version is the CLI package version.
