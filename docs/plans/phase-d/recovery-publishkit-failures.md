# PR890 Windows publish-kit failure triage

## Evidence boundary

This is a classification of retained artifacts under `/tmp/pr890-ci-inventory/`, not a rerun or a claim about current-head Windows behavior. The source run was PR890 at `f784149d3d71d37bacae21f7eee9f5737dc549d3`; job `111051437138` reported 33 failed, 240 passed, and 14 skipped. For 27 failures, the log directly shows a bare-`bash` child-process failure: ten include UTF-16LE text from the unconfigured Windows Subsystem for Linux (WSL) stub, and 17 show `CompletedProcess(args=['bash'])` with a nonzero status. Five other failures expose only downstream symptoms, so a shared shell-setup cause is inferred rather than directly shown by the log. The remaining failure is an independently evidenced renderer wrapper path expectation. The workflow step shell itself is Git for Windows Bash; Python's bare executable lookup is a separate path and selected WSL for the directly evidenced failures.

The log directly establishes child-process shell failures for 27 tests; it does not directly identify the shell selection for the five inferred cases. Their missing `output` or `github-output` files and empty or generic assertion results are downstream symptoms consistent with the shared setup failure, not independent product defects established by this log. The renderer wrapper path mismatch is a separate platform-specific failure. Preserve the assertions and fix the shared test harness / expected platform path. These retained historical logs do not prove whether a correction passes on a later recovery head.

## Dedupe and bounded follow-up scopes

The CI duplicate-execution ledger in `docs/ci-policy.md` retains the complete installed `.github/scripts/tests` suite in `manifest-validation (ubuntu)`. It removes the later focused `test_release_artifacts` `-k manifest or publish_order` subset because that suite is a strict superset. It also removes the duplicate Linux sc-lint receipt-rejection execution from sc-lint preflight while retaining that preflight's Windows execution. Those removals are executions only: none of the 33 historical assertions above is deleted. Stage 2 keeps platform configuration unchanged; native Windows qualification is a later stage and must not be replaced by another copy of the PR suite.
