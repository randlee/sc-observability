# PR890 Windows publish-kit failure triage

## Evidence boundary

This is a classification of retained artifacts under `/tmp/pr890-ci-inventory/`, not a rerun or a claim about current-head Windows behavior. The source run was PR890 at `f784149d3d71d37bacae21f7eee9f5737dc549d`; job `111051437138` reported 33 failed, 240 passed, and 14 skipped. Its saved log records child processes launched as bare `bash` returning UTF-16LE text from the unconfigured Windows Subsystem for Linux (WSL) stub. The workflow step shell itself is Git for Windows Bash; Python's bare executable lookup is a separate path and selected WSL instead.

The log therefore establishes a test-process selection failure, not 32 independent publish-product failures. In tests where the child never ran, missing `output` or `github-output` files are downstream symptoms. The one exception is a platform-specific virtualenv path expectation. Preserve the assertions and fix the shared test harness / expected platform path. These retained historical logs do not prove whether a correction passes on a later recovery head.

## Dedupe and bounded follow-up scopes

The CI duplicate-execution ledger in `docs/ci-policy.md` retains the complete installed `.github/scripts/tests` suite in `manifest-validation (ubuntu)`. It removes the later focused `test_release_artifacts` `-k manifest or publish_order` subset because that suite is a strict superset. It also removes the duplicate Linux sc-lint receipt-rejection execution from sc-lint preflight while retaining that preflight's Windows execution. Those removals are executions only: none of the 33 historical assertions above is deleted. Stage 2 keeps platform configuration unchanged; native Windows qualification is a later stage and must not be replaced by another copy of the PR suite.
