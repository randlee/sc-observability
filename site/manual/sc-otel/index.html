sc-otel

Send one log record, one completed span or one metric measurement to an OTLP/HTTP collector with the official OpenTelemetry exporter. Each command exports before it exits and reports the exporter's result; nothing is stored or retried after the process ends.

Usage: sc-otel [OPTIONS] <COMMAND>

Commands:
  log     Export one log record
  span    Export one completed span
  metric  Export one metric measurement
  help    Print this message or the help of the given subcommand(s)

Options:
      --endpoint <URL>
          OTLP/HTTP base URL; /v1/logs, /v1/traces or /v1/metrics is appended. Defaults to `OTEL_EXPORTER_OTLP_ENDPOINT`, then <http://localhost:4318>

      --header <NAME=VALUE>
          Send a request header as NAME=VALUE; repeat for more. Replaces a header of the same name from `OTEL_EXPORTER_OTLP_HEADERS`. Prefer that variable for credentials: command lines are visible to other processes

      --timeout <SECONDS>
          Bound OTLP connection, requests and exporter retries only; input reads may block until EOF. Defaults to 3 seconds; whole seconds greater than zero

      --root-certificate <FILE>
          Trust the CA certificates in this PEM file in addition to the system roots

      --service <NAME>
          Resource service.name. Defaults to `OTEL_SERVICE_NAME`, then the SDK default `unknown_service`. `OTEL_RESOURCE_ATTRIBUTES` adds further resource attributes

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

QUICK START
  sc-otel log --body 'job started'
  sc-otel span --name build --start-time-unix-nano 1700000000000000000
  sc-otel metric --name jobs.completed --kind counter --value 1

  Each command builds one native OpenTelemetry record and exports it with the
  official OTLP/HTTP protobuf exporter before the process exits. No Tokio
  runtime, local database or background worker is involved.

CONFIGURATION
  Endpoint: --endpoint, then OTEL_EXPORTER_OTLP_ENDPOINT, then
  http://localhost:4318. The signal path (/v1/logs, /v1/traces, /v1/metrics)
  is appended, so per-signal *_ENDPOINT variables are not consulted.

  Headers: OTEL_EXPORTER_OTLP_HEADERS and the per-signal *_HEADERS variables
  are sent with every request. --header NAME=VALUE replaces a header of the
  same name. Keep credentials in the environment rather than on the command
  line. This thin CLI does not read SC_OTEL_AUTH_HEADER; ADR-023 supersedes
  ADR-021's submission architecture for Phase H. Use the standard
  OTEL_EXPORTER_OTLP_HEADERS or per-signal *_HEADERS variables instead.
  Header values and endpoint user information never appear in errors.

  Resource: --service sets service.name; otherwise OTEL_SERVICE_NAME and
  OTEL_RESOURCE_ATTRIBUTES apply as in the OpenTelemetry SDK.

  TLS: https endpoints verify certificates against the system roots plus any
  --root-certificate PEM file. Verification cannot be disabled.

ATTRIBUTES
  --attributes takes one JSON object of string, boolean and number values,
  inline, as @FILE, or as - to read standard input:
    sc-otel log --body done --attributes '{"job":"build","attempt":2}'
  Reads from @FILE and - wait until EOF and can block while a pipe, terminal
  or FIFO remains open. The global --timeout bounds OTLP export only; it does
  not bound these input reads.
  Input is limited to 1 MiB and 10,000 attributes. Null, array and object
  values are rejected. If an object repeats a key, each occurrence is sent in
  input order and the receiver decides how to treat the duplicates.
  Unsigned integers greater than i64::MAX are converted to exact decimal
  strings. Integer literals outside the i64 and u64 ranges are rejected;
  float literals are accepted as floats.

EXIT CODES
  0  The exporter reported success.
  1  Unexpected internal failure.
  2  Command-line usage error; inspect stderr and --help.
  3  Input or configuration rejected; nothing was exported.
  7  The export failed: the collector was unreachable, timed out or rejected
     the request. Nothing is retried after the process exits.

  Success means the collector accepted the request. For metrics, the
  OpenTelemetry SDK 0.33.0 reports a failed export without the HTTP cause.

DOCUMENTATION
  Run sc-otel <command> --help for options and examples.
  The Markdown manual and website reference are generated from this same Clap
  help at every release; their version is the CLI package version.

sc-otel log

Export one log record

Usage: sc-otel log [OPTIONS] --body <BODY>

Options:
      --body <BODY>
          Log message body

      --endpoint <URL>
          OTLP/HTTP base URL; /v1/logs, /v1/traces or /v1/metrics is appended. Defaults to `OTEL_EXPORTER_OTLP_ENDPOINT`, then <http://localhost:4318>

      --header <NAME=VALUE>
          Send a request header as NAME=VALUE; repeat for more. Replaces a header of the same name from `OTEL_EXPORTER_OTLP_HEADERS`. Prefer that variable for credentials: command lines are visible to other processes

      --severity <SEVERITY>
          Log severity
          
          [default: info]
          [possible values: trace, debug, info, warn, error, fatal]

      --timeout <SECONDS>
          Bound OTLP connection, requests and exporter retries only; input reads may block until EOF. Defaults to 3 seconds; whole seconds greater than zero

      --trace-id <HEX>
          Correlate the record with this trace (32 hex digits). Requires --span-id

      --root-certificate <FILE>
          Trust the CA certificates in this PEM file in addition to the system roots

      --span-id <HEX>
          Correlate the record with this span (16 hex digits). Requires --trace-id

      --attributes <JSON|@FILE|->
          Attributes as one JSON object of string, boolean or number values: inline JSON, @FILE, or - for standard input. Reads from @FILE and - wait until EOF; --timeout does not bound input reads. At most 1 MiB and 10,000 attributes

      --service <NAME>
          Resource service.name. Defaults to `OTEL_SERVICE_NAME`, then the SDK default `unknown_service`. `OTEL_RESOURCE_ATTRIBUTES` adds further resource attributes

  -h, --help
          Print help (see a summary with '-h')

Examples:
  sc-otel log --body 'job started'
  sc-otel log --severity error --body 'job failed' --attributes '{"job":"build","attempt":2}'
  sc-otel log --body done --trace-id 4bf92f3577b34da6a3ce929d0e0e4736 --span-id 00f067aa0ba902b7

sc-otel span

Export one completed span

Usage: sc-otel span [OPTIONS] --name <NAME>

Options:
      --endpoint <URL>
          OTLP/HTTP base URL; /v1/logs, /v1/traces or /v1/metrics is appended. Defaults to `OTEL_EXPORTER_OTLP_ENDPOINT`, then <http://localhost:4318>

      --name <NAME>
          Span name

      --header <NAME=VALUE>
          Send a request header as NAME=VALUE; repeat for more. Replaces a header of the same name from `OTEL_EXPORTER_OTLP_HEADERS`. Prefer that variable for credentials: command lines are visible to other processes

      --trace-id <HEX>
          Trace id (32 hex digits). Defaults to a new random id

      --span-id <HEX>
          Span id (16 hex digits). Defaults to a new random id

      --timeout <SECONDS>
          Bound OTLP connection, requests and exporter retries only; input reads may block until EOF. Defaults to 3 seconds; whole seconds greater than zero

      --parent-span-id <HEX>
          Parent span id (16 hex digits); a supplied id is local unless provenance is explicit. Requires --trace-id

      --root-certificate <FILE>
          Trust the CA certificates in this PEM file in addition to the system roots

      --kind <KIND>
          Span kind
          
          [default: internal]
          [possible values: internal, server, client, producer, consumer]

      --service <NAME>
          Resource service.name. Defaults to `OTEL_SERVICE_NAME`, then the SDK default `unknown_service`. `OTEL_RESOURCE_ATTRIBUTES` adds further resource attributes

      --start-time-unix-nano <NANOS>
          Start time in nanoseconds since the Unix epoch. Defaults to the end time

      --end-time-unix-nano <NANOS>
          End time in nanoseconds since the Unix epoch. Defaults to now

      --ok
          Set the span status to Ok

      --error <DESCRIPTION>
          Set the span status to Error with this description

      --attributes <JSON|@FILE|->
          Attributes as one JSON object of string, boolean or number values: inline JSON, @FILE, or - for standard input. Reads from @FILE and - wait until EOF; --timeout does not bound input reads. At most 1 MiB and 10,000 attributes

  -h, --help
          Print help (see a summary with '-h')

Examples:
  sc-otel span --name build --start-time-unix-nano 1700000000000000000 --end-time-unix-nano 1700000005000000000
  sc-otel span --name deploy --kind client --error 'rollout timed out' --attributes @span.json

Without --trace-id and --span-id the span gets new random ids. Pass the ids of a parent span with --trace-id and --parent-span-id to join an existing trace. A parent supplied this way is recorded as local; this CLI does not mark it remote.

sc-otel metric

Export one metric measurement

Usage: sc-otel metric [OPTIONS] --name <NAME> --kind <KIND> --value <VALUE>

Options:
      --endpoint <URL>
          OTLP/HTTP base URL; /v1/logs, /v1/traces or /v1/metrics is appended. Defaults to `OTEL_EXPORTER_OTLP_ENDPOINT`, then <http://localhost:4318>

      --name <NAME>
          Instrument name

      --header <NAME=VALUE>
          Send a request header as NAME=VALUE; repeat for more. Replaces a header of the same name from `OTEL_EXPORTER_OTLP_HEADERS`. Prefer that variable for credentials: command lines are visible to other processes

      --kind <KIND>
          Instrument kind
          
          [possible values: counter, up-down-counter, gauge, histogram]

      --timeout <SECONDS>
          Bound OTLP connection, requests and exporter retries only; input reads may block until EOF. Defaults to 3 seconds; whole seconds greater than zero

      --value <VALUE>
          Measurement value

      --root-certificate <FILE>
          Trust the CA certificates in this PEM file in addition to the system roots

      --unit <UNIT>
          Instrument unit, such as s or By

      --description <DESCRIPTION>
          Instrument description

      --service <NAME>
          Resource service.name. Defaults to `OTEL_SERVICE_NAME`, then the SDK default `unknown_service`. `OTEL_RESOURCE_ATTRIBUTES` adds further resource attributes

      --attributes <JSON|@FILE|->
          Attributes as one JSON object of string, boolean or number values: inline JSON, @FILE, or - for standard input. Reads from @FILE and - wait until EOF; --timeout does not bound input reads. At most 1 MiB and 10,000 attributes

  -h, --help
          Print help (see a summary with '-h')

Examples:
  sc-otel metric --name jobs.completed --kind counter --value 1
  sc-otel metric --name queue.depth --kind gauge --value 42 --attributes '{"queue":"default"}'
  sc-otel metric --name job.duration --kind histogram --unit s --value 12.5

Counter and histogram values, including negative and non-finite values, are passed to the OpenTelemetry SDK without CLI range validation. An invalid instrument name records nothing, sends no request, and fails with exit 3.
